Configuration

SshDataBridge.load_config — Function
load_config(path::AbstractString)::BridgeConfig

Read, parse, and validate the TOML configuration file at path. Every failure is reported as ArgumentError: a missing or unreadable file, a path that cannot be inspected, a file that grants any permission to group or others (it holds passwords; use mode 600), a TOML syntax error, and every validation failure. A syntax error is reported by its kind and line number only: the offending line may be a password line and is never printed.

source
SshDataBridge.parse_config — Function
parse_config(dict::AbstractDict; config_dir::AbstractString=pwd())::BridgeConfig

Build a validated BridgeConfig from a parsed TOML dictionary. Every table is checked for unknown keys and every value for its expected type. [push].local_source_dir, [pull].local_destination_root, and the target keys name, host, and remote_dir are mandatory, password with auth = "password" (the default); every other key has a default or, as port and user, is left to ~/.ssh/config when absent. Relative local paths are resolved against config_dir.

SshDataBridge.BridgeConfig — Type
BridgeConfig

Complete configuration: global transport options, push and pull parameters, and the non-empty list of targets. Target names must be unique, because each one names the local harvest directory of its target and two targets harvested concurrently into the same directory would overwrite each other's results. Two targets on the same host and port must not have overlapping remote directories, equal or one inside the other, because a project purge of one would remove the output of the other before it is harvested, and both would be deployed into one tree. The rule does not depend on purge_scope. Hosts are compared as node_key describes, IP addresses by value, with port 22 for a target whose port ~/.ssh/config decides. This is the lexical check on the configured values; it concerns hosts, not storage, and does not recognize an sshconfig alias and the name it stands for, two names or addresses of one machine, nodes that mount one filesystem, or a symbolic link or bind mount on the node. The command-line driver repeats it on the configuration that ssh evaluates for every target (see [`checkendpointoverlaps](@ref)), and the ownership marker (see [claimscript](@ref), [purge_script`](@ref)) covers nodes that share storage. The functions that take a single target act on the target they are given.

SshDataBridge.GlobalOptions — Type
GlobalOptions

Transport parameters shared by all targets.

Fields

  • connect_timeout::Int: SSH connection timeout in seconds.
  • strict_host_key_checking::String: default host key policy ("accept-new", "yes", "no").
  • compress::Bool: whether rsync compresses in flight (-z).
  • bandwidth_limit::Int: bandwidth cap in KiB/s per transfer (rsync --bwlimit); 0 means unlimited.
  • server_alive_interval::Int: seconds of silence from the server after which ssh sends a keepalive request (ServerAliveInterval); 0 leaves keepalive to the ssh client configuration.
  • server_alive_count_max::Int: unanswered keepalive requests after which ssh drops the connection (ServerAliveCountMax).

ssh abandons a connection after server_alive_interval * (server_alive_count_max + 1) seconds without an answer from the server, 60 s with the defaults, so the transfer or remote command fails instead of blocking. A session that runs through an existing master connection (ControlMaster) is kept alive by the master, whose own options govern; these two fields do not reach it.

SshDataBridge.PushOptions — Type
PushOptions

Parameters of the push action.

Fields

  • local_source_dir::String: local project directory to deploy; mandatory in the configuration.
  • excludes::Vector{String}: rsync exclude patterns.
  • require_clean_git::Bool: abort when the local git working tree has uncommitted changes.
  • use_gitignore::Bool: honor the .gitignore rules of the source tree during deployment.
  • includes::Vector{String}: rsync include patterns applied before the .gitignore filter, re-admitting paths the deployed project ignores; excludes take precedence. Empty by default.
source
SshDataBridge.PullOptions — Type
PullOptions

Parameters of the pull action.

Fields

  • local_destination_root::String: local root under which one directory per target is created; mandatory in the configuration. It also holds the rsync logs of every target, see transfer_log_path.
  • output_subdir::String: default output directory relative to each target's remote_dir.
  • includes::Vector{String}: rsync include patterns; empty means everything.
  • excludes::Vector{String}: rsync exclude patterns.
  • collision_strategy::Symbol: :resume, :backup, or :abort when the local directory exists.
  • clean_remote_after_pull::Bool: purge the remote directory after a verified harvest.
  • purge_scope::Symbol: directory removed by a purge: :project (the whole base directory, the default) or :output (the output directory only).

clean_remote_after_pull cannot be combined with includes: a purge after a harvest narrowed by include patterns would destroy the files the filter left behind.

SshDataBridge.BridgeTarget — Type
BridgeTarget

A remote compute node and the layout of its campaign directory.

Fields

  • name::String: unique label; it also names the local harvest directory.
  • host::String: DNS hostname, ssh_config Host alias, IPv4 address, or IPv6 literal.
  • port::Union{Nothing, Int}: SSH daemon port in 1:65535; nothing leaves it to ~/.ssh/config.
  • user::Union{Nothing, String}: remote user name; nothing leaves it to ~/.ssh/config or the local account name.
  • auth::Symbol: :password (the password is fed to sshpass) or :key (no secret; ssh authenticates by agent, identity file, certificate, or an existing master connection, as ~/.ssh/config provides).
  • password::Union{Nothing, String}: remote password of a password target, nothing for a key target; never printed by show.
  • identity_file::Union{Nothing, String}: private key of a key target, or a public key selecting an agent key, stored with a leading ~/ expanded (-i <path> -o IdentitiesOnly=yes).
  • proxy_jump::Union{Nothing, String}: jump-host specification of a key target (-J), or "none" (any target; accepted in any letter case and stored as "none") to connect directly whatever ~/.ssh/config routes (-o ProxyCommand=none).
  • remote_dir::String: absolute base directory of the campaign on the remote host.
  • output_subdir::String: output directory relative to remote_dir (default "output").
  • strict_host_key_checking::Union{String, Nothing}: optional host key policy override.

remote_dir and output_subdir are stored normalized: . segments, repeated slashes, and trailing slashes are removed on construction, so that every command names the directory in one spelling. An output_subdir that is . itself stays ., the base directory.

Constructors

BridgeTarget(name, host; remote_dir, port=nothing, user=nothing, auth=:password,
             password=nothing, identity_file=nothing, proxy_jump=nothing,
             output_subdir="output", strict_host_key_checking=nothing)
BridgeTarget(name, host, port, user, password, remote_dir, output_subdir="output",
             strict_host_key_checking=nothing)

The positional form builds a password target. Every field is checked by validate_bridge_target_fields.

Examples

BridgeTarget("node01", "node01.cluster.example", 22, "researcher", "secret",
             "/home/researcher/campaign")
BridgeTarget("cluster", "hpc"; auth=:key, remote_dir="/scratch/researcher/campaign")

SshDataBridge.probe_target — Function
probe_target(target::BridgeTarget, globals::GlobalOptions)::ProbeResult

Check SSH reachability of target, the presence of rsync on the remote host, and the existence of the base and output directories. Connection, authentication, and spawn failures are reported through the result, never thrown; only a key target whose prerequisites fail (check_key_target_prerequisites) raises their ArgumentError when its command is built. A key target refused with Permission denied, or whose route raised a prompt (see prompt_refusal_environment), gets a hint in the message: no prompt is allowed, so the key must be in the agent, or a master connection must be open when the host asks for a second factor. A key target that fails with Host key verification failed, or whose route asked to confirm a host key, gets one as well: the confirmation cannot be answered, and strict_host_key_checking is not passed on to jump hosts, whose host-key policy comes from ~/.ssh/config. Both hints name the interactive command of interactive_ssh_command.

SshDataBridge.push_target — Function
push_target(target::BridgeTarget, config::BridgeConfig; dry_run::Bool=false)::TransferResult

Deploy the local source tree to one target. The log directory (local_destination_root) is created first, then remote_dir on the node is created and claimed for the target (see claim_remote_directory), then rsync runs; the first step that fails ends the push with a failed result. A directory that another target has claimed refuses the push. On success the message gives the number of files and bytes transferred and the log path.

SshDataBridge.push_all_targets — Function
push_all_targets(config::BridgeConfig; dry_run::Bool=false)::Vector{TransferResult}

Deploy the local source tree to all configured targets concurrently. The source tree must exist, otherwise ArgumentError is thrown; when config.push.require_clean_git is set, it must also be a clean git working tree. Both checks run in dry-run mode as well.

SshDataBridge.pull_target — Function
pull_target(target::BridgeTarget, config::BridgeConfig; dry_run::Bool=false,
            clean_remote::Bool=config.pull.clean_remote_after_pull)::TransferResult

Harvest the output directory of one target into local_destination_root/<name>/. When clean_remote is set (by default it follows config.pull.clean_remote_after_pull), the directory selected by config.pull.purge_scope is purged afterwards, but only if verify_harvest finds the local copy complete. An incomplete harvest or a failed purge leaves the remote directory in place and fails the target, although the data were retrieved. With config.pull.includes set, a requested purge is refused with ArgumentError before any transfer, because files left behind by the filter would be destroyed. A local destination that cannot be prepared fails the target. Transferred files are appended to the log of transfer_log_path; the message gives the file count, the size, and the log path.

SshDataBridge.clean_remote_target — Function
clean_remote_target(target::BridgeTarget, globals::GlobalOptions;
                    scope::Symbol=:project, dry_run::Bool=false)::TransferResult

Remove the directory selected by scope (see purge_path) on the remote host with the script of purge_script, run under sh -c; the default removes the whole project directory. The path is checked with validate_remote_path_safety before any command is issued, against target.user or, when the target leaves the user to ~/.ssh/config, the user that resolve_endpoint evaluates. A refusal, by that check, by the evaluation, or by the script, is reported as a failed result. A purge that found no ownership marker of the target on the path says so in its message.

SshDataBridge.ProbeResult — Type
ProbeResult

Outcome of probe on one target.

Fields

  • target::BridgeTarget: the probed target.
  • success::Bool: SSH reachable and rsync present on the remote host.
  • ssh_ok::Bool: the probe command exited with status zero.
  • rsync_ok::Bool: rsync is installed on the remote host.
  • remote_dir_exists::Bool: the base directory exists.
  • remote_output_dir_exists::Bool: the output directory exists.
  • message::String: diagnostics, as printed in the summary.
source
SshDataBridge.TransferResult — Type
TransferResult

Outcome of a push, pull, or clean action on one target.

Fields

  • target::BridgeTarget: the affected target.
  • action::Symbol: :push, :pull, or :clean.
  • success::Bool: whether the action completed with exit status zero.
  • exit_code::Int: exit status of the underlying process, or -1 when no process produced one: the command could not be started, or the step was refused locally (unsafe purge path, unusable local directory, incomplete harvest).
  • duration_seconds::Float64: wall-clock duration.
  • message::String: outcome, as printed in the summary; never contains credentials.

Command-line driver

SshDataBridge.main — Function
main(args::AbstractVector{<:AbstractString}=ARGS; io::IO=stdout, err::IO=stderr)::Int

Run the command-line driver (probe, push, pull, clean; see usage) and return the exit status instead of calling exit: 0 when every target succeeded, 1 on a usage, configuration, or precondition error, 2 when at least one target failed. Summary tables, and the usage text when --help is given, go to io; error messages, the usage text after a usage error, and log records go to err. scripts/run.jl is a thin wrapper around this function.

Example

exit(main(["probe", "--config", "config.toml"]))
