Internals

The functions and constants behind the API: validators, command builders, process runners, and the purge helpers. None of them is exported, and any of them may change in a release.

Fields

  • action::Symbol: :help, :probe, :push, :pull, or :clean.
  • config_path::String: configuration file to load.

SshDataBridge.check_endpoint_overlaps — Method
check_endpoint_overlaps(targets::AbstractVector{BridgeTarget},
                        endpoints::AbstractVector{SshEndpoint})

Repeat the overlap rule of BridgeConfig on the configuration that ssh evaluates: endpoints[i] belongs to targets[i]. Two targets whose endpoints have the same node_key of host name and port must not have overlapping remote directories, so that an ssh_config alias and the name it stands for, or a port that only ~/.ssh/config sets, cannot hide two targets on one node. Throws ArgumentError for the first such pair, DimensionMismatch when the lengths differ.

The route (ProxyJump, ProxyCommand) is deliberately not part of the key: two routes to one machine must not pass. Two machines with one private name behind different gateways are refused as well; this false refusal is the safe error, and distinct remote directories avoid it.

SshDataBridge.claim_script — Method
claim_script(remote_dir::AbstractString, name::AbstractString)::String

One-line POSIX shell script, run under sh -c, that creates remote_dir with mkdir -p and claims it for the target name through the ownership marker remote_dir/.sshdatabridge-target, which holds the name of the target. An absent marker is written to a temporary file named after the node and the shell's process ID, then hard-linked into place; the link is atomic and fails when the marker exists, also over NFS, where O_EXCL is not reliable on every server (open(2)). Of two concurrent claims of one directory exactly one marker is written, and both read it back rather than trust the status of ln, which NFS can report as failed after a lost reply. The physical location of the directory is resolved, and the claim is refused when a marker of another target lies in any ancestor or anywhere below it, so that a directory nested in the tree of another target is caught as well. That check runs before the marker is written and, by a claim whose link created the marker (the marker and its temporary file are one inode, which holds after a lost NFS reply as well), again afterwards: of two concurrent claims of nested directories each writes its own marker before its second check, so at least one of them sees the other's marker, removes its own, and refuses (both may refuse). A claim that found the marker in place, or lost the link to a concurrent claim of the same name, never removes it. The script exits 0 when the marker names name, 1 when the directory or the marker cannot be created, entered, or read (a file system without hard links included), and 97 when the marker, or one above or below the directory, names another target: the nodes share storage, or two targets name one directory or nested ones. The refusal states its reason on standard error. remote_dir and name are POSIX-quoted.

SshDataBridge.is_valid_proxy_jump — Method
is_valid_proxy_jump(spec::AbstractString)::Bool

Whether spec is a jump-host specification accepted for ssh -J: one or more [user@]host[:port] hops separated by commas, an IPv6 host enclosed in square brackets, or exactly none, which disables a ProxyJump or ProxyCommand set in ~/.ssh/config. Each user must be a valid account name, each host a valid host name, alias, or IPv4 address (an IPv6 literal only in brackets), and each port lie in 1:65535. Empty specifications and hops, control characters, and ssh:// URIs are refused. A bracketed IPv6 host is accepted in the last hop only: OpenSSH inserts the hops before the last unquoted into the command it builds for the last jump host and runs that command with the user's shell ($SHELL -c), which would read the brackets as a glob pattern. The other characters a hop admits (letters, digits, ., _, -, @, :, ,) are not special to the usual shells.

SshDataBridge.pull_filter_arguments — Method
pull_filter_arguments(pull_opts::PullOptions)::Vector{String}

rsync filter rules of a harvest. The ownership marker at the root of the transfer (see claim_script) is excluded first, so that it is never harvested nor compared by the verification pass; with output_subdir = "." the output directory is the project directory. Exclude patterns come next and therefore take precedence. When include patterns are given, the harvest is narrowed to files matching one of them: every directory is entered (--include=*/), the include patterns follow, a final --exclude=* drops everything else, and --prune-empty-dirs omits directories left without files. Include rules alone would not narrow anything, because rsync transfers every file that no rule excludes.

SshDataBridge.purge_script — Method
purge_script(path::AbstractString, name::AbstractString)::String

One-line POSIX shell script that removes path recursively on the node for the target name. It exits 0 when the path does not exist. It exits 98, deleting nothing, when the path is a symbolic link, whose removal would leave the deployed tree in place; when the path or the home directory of the account cannot be entered (a file, or a directory without search permission), so that their physical locations cannot be compared; and when the path is a directory that contains the home directory, which the lexical rules of validate_remote_path_safety cannot see. It also exits 98 when an ownership marker of another target (see claim_script) lies in the physical location of the path or in any of its ancestors, or anywhere below it. Without any marker of name on the path the purge proceeds and notes this on standard error (purge note:). Each refusal states its reason on standard error. path and name are POSIX-quoted, path without a trailing slash, so that the link test sees a link and not the directory behind it.

SshDataBridge.run_authenticated — Method
run_authenticated(cmd::Cmd, password::AbstractString)

Run cmd, whose first words must be sshpass -d 0, feeding password followed by a newline through standard input so that the secret never appears in any process environment or argument vector. Returns (; exitcode, stdout, stderr) and throws nothing: a non-zero exit status is reported, a signal-terminated child reports 128 + signal, and a command that cannot be started reports -1 with the reason in stderr. Base.IOError raised while writing the password is ignored, because it only means the child exited before reading it (for example a refused connection).

Both streams are read to end-of-file. Buffers handed to pipeline are not enough on Julia 1.10, where wait returns when the child exits, not when its output has been copied, so that the output could be read incomplete or empty.

SshDataBridge.ssh_config_command — Method
ssh_config_command(target::BridgeTarget, globals::GlobalOptions)::Cmd

ssh -G with the options of ssh_options, the destination of target, and the remote command sh -c true: ssh prints the configuration it would use and never connects, so the command needs neither sshpass nor the environment of prompt_refusal_environment. The remote command makes ssh evaluate the session as the commands of the package are evaluated, a command session, which Match sessiontype (OpenSSH 10.0) tells apart from an interactive one. A Match command block that tells the shell commands of the package from rsync's rsync --server is not seen. -o RemoteCommand=none keeps a RemoteCommand of the host's block from making the query fail ("Cannot execute command-line and remote command"); the commands of such a target still fail, that target alone.

source
SshDataBridge.ssh_options — Method
ssh_options(target::BridgeTarget, globals::GlobalOptions)::Vector{String}

ssh options shared by the direct commands, the rsync transport, and ssh -G: the port when the target sets one, host-key policy, connection timeout, keepalive (see keepalive_options), then the authentication options of the target.

A password target pins authentication to passwords. Public-key authentication is disabled and the preferred methods are keyboard-interactive and password, so that an agent holding many keys cannot exhaust the server's authentication attempts and an encrypted key cannot raise a passphrase prompt that sshpass does not answer; one password prompt is allowed.

A key target sets BatchMode=yes, so that ssh fails instead of prompting, followed by -i <identity_file> -o IdentitiesOnly=yes and -J <proxy_jump> when these are set; everything else is left to ~/.ssh/config. proxy_jump = "none", the one value a password target admits, is passed as -o ProxyCommand=none, which overrides both a ProxyJump and a ProxyCommand of ~/.ssh/config (-J none overrides only the former).

SshDataBridge.validate_identity_file — Method
validate_identity_file(path::AbstractString, context::AbstractString)

Require path, already expanded by expand_identity_file, to name a key file that ssh opens as given and that the remote-shell string of rsync can carry: free of control characters, of single quotes, and of % and $, which ssh expands in an identity path (%d, ${HOME}) after the check made here, absolute, and a regular file. A private key must have no group or other permission bits, which ssh refuses for a key of its owner; a public key (.pub), which selects the key of an agent or a security token, is exempt. The file content is never read. Throws ArgumentError naming the violated condition, also when the path cannot be inspected; context names the target in the message.
