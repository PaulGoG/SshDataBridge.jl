Internals

The functions and constants behind the API: validators, command builders, process runners, and the purge helpers. None of them is exported, and any of them may change in a release.

SshDataBridge.CliOptions — Type
CliOptions

Parsed command line of the driver.

Fields

  • action::Symbol: :help, :probe, :push, :pull, or :clean.
  • config_path::String: configuration file to load.
  • dry_run::Bool: print the commands without executing them.
  • clean_remote::Bool: purge the remote directory after a verified harvest.
  • confirmed::Bool: --yes was given, confirming remote deletion.
  • targets::Vector{String}: names of the targets to act on; empty means every configured target.

SshDataBridge.node_key — Method
node_key(host::AbstractString, port::Integer)::Tuple{String, Int}

Identity of an ssh endpoint when targets are compared: the host and the port. A host name is taken in lower case without a trailing dot. An IP address is taken by its value (see numeric_address), so that its spellings give one key: IPv6 groups written in full or compressed, in either letter case, an IPv4 address mapped into IPv6, a shortened IPv4 form. A name and its address, or two names of one machine, are not recognized as the same node.

SshDataBridge.numeric_address — Method
numeric_address(host::AbstractString)::Union{Tuple{Int, UInt128}, Nothing}

The address of a numeric host as the C library reads it, and therefore as ssh connects to it: (6, value) for an IPv6 literal (inet_pton), (4, value) for an IPv4 address, shortened forms such as 192.0.522 included (inet_aton). An IPv4 address mapped into IPv6 (::ffff:a.b.c.d) is returned as that IPv4 address. nothing when host is not numeric or the C library does not read it as an address.

SshDataBridge.pull_filter_arguments — Method
pull_filter_arguments(pull_opts::PullOptions)::Vector{String}

rsync filter rules of a harvest. Exclude patterns come first and therefore take precedence. When include patterns are given, the harvest is narrowed to files matching one of them: every directory is entered (--include=*/), the include patterns follow, a final --exclude=* drops everything else, and --prune-empty-dirs omits directories left without files. Include rules alone would not narrow anything, because rsync transfers every file that no rule excludes.

SshDataBridge.purge_script — Method
purge_script(path::AbstractString)::String

One-line POSIX shell script that removes path recursively on the node. It exits 0 when the path does not exist. It exits 98, deleting nothing, when the path is a symbolic link, whose removal would leave the deployed tree in place; when the path or the home directory of the account cannot be entered (a file, or a directory without search permission), so that their physical locations cannot be compared; and when the path is a directory that contains the home directory, which the lexical rules of validate_remote_path_safety cannot see. Each refusal states its reason on standard error. path is POSIX-quoted, without a trailing slash, so that the link test sees a link and not the directory behind it.

source
SshDataBridge.push_filter_arguments — Method
push_filter_arguments(push_opts::PushOptions)::Vector{String}

rsync filter rules of a deployment, in precedence order: the exclude patterns, then the include patterns, then the dir-merge filter that applies the .gitignore of the source tree. rsync takes the first matching rule, so an exclude always wins and an include re-admits a path that .gitignore would drop (/Manifest.toml, for example).

SshDataBridge.rsync_base_arguments — Method
rsync_base_arguments(globals::GlobalOptions)::Vector{String}

Leading arguments shared by every rsync invocation: the sshpass prefix, the archive and resumption flags, -s (--secluded-args), and the optional compression and bandwidth settings. SshDataBridge.run_authenticated — Method
run_authenticated(cmd::Cmd, password::AbstractString)

Run cmd, whose first words must be sshpass -d 0, feeding password followed by a newline through standard input so that the secret never appears in any process environment or argument vector. Returns (; exitcode, stdout, stderr) and throws nothing: a non-zero exit status is reported, a signal-terminated child reports 128 + signal, and a command that cannot be started reports -1 with the reason in stderr. Base.IOError raised while writing the password is ignored, because it only means the child exited before reading it (for example a refused connection).

Both streams are read to end-of-file. Buffers handed to pipeline are not enough on Julia 1.10, where wait returns when the child exits, not when its output has been copied, so that the output could be read incomplete or empty.

SshDataBridge.run_captured — Method
run_captured(cmd::Cmd)

Run a command that needs no credentials, capturing standard output and standard error, both read to end-of-file as in run_authenticated. Returns (; exitcode, stdout, stderr); a non-zero exit status is reported, not thrown, and a signal-terminated child reports 128 + signal.

SshDataBridge.ssh_options — Method
ssh_options(target::BridgeTarget, globals::GlobalOptions)::Vector{String}

ssh options shared by the direct commands and the rsync transport: port, host-key policy, connection timeout, keepalive (see keepalive_options), and authentication pinned to passwords. Public-key authentication is disabled and the preferred methods are keyboard-interactive and password, so that an agent holding many keys cannot exhaust the server's authentication attempts and an encrypted key cannot raise a passphrase prompt that sshpass does not answer; one password prompt is allowed.

SshDataBridge.validate_remote_path_safety — Method
validate_remote_path_safety(path::AbstractString, user::AbstractString)

Verify that path may be removed recursively on a remote host. The path must be absolute, free of control characters and .. segments, at least two components deep, and neither the filesystem root, /root, /home, the home directory of user, nor located under a protected system directory (/usr, /etc, /var, ...). Throws ArgumentError otherwise.

SshDataBridge.verify_harvest — Method

Run the verification pass of build_verification_command and return (; complete, detail). The harvest counts as complete only when the pass exits with status zero and prints nothing; any output line is an item that changed on the remote since the transfer (a job still writing, for example). detail explains an incomplete harvest and is empty otherwise.
